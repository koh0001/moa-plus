# v2.0 실기기 실측 테스트 체크리스트

시뮬레이터/유닛 테스트로 확인 불가능한 것들 — **실제 손가락의 속도·꼬리·드리프트**가
변수인 항목들이다. 실기기(가능하면 평소 쓰는 아이폰)에 설치해 메모 앱에서 확인한다.
각 항목은 "순정 실측 근거 → 기대 동작" 순. 이상하면 그대로 두고 어떤 글자가
나왔는지 기록해 주면 영상 판독 데이터와 대조할 수 있다.

## A. 새 입력 경로 (이번 업데이트로 새로 되는 것)

- [ ] **A1. 대각선 왕복 ㅐ** — ㅇ 키에서 ↗로 나갔다 ↙로 되돌아오기 ×10 → "애".
      삼성에서 쓰던 손버릇 그대로. 성공률과, 실패 시 나온 글자(이? 야?) 기록.
- [ ] **A2. 대각선 왕복 ㅔ** — ↖ 나갔다 ↘ 복귀 ×10 → "에".
- [ ] **A3. 대각선 왕복 ㅢ** — ↙ 나갔다 ↗ 복귀 ×10 → "의". (기존에도 되던 경로 — 회귀 확인)
- [ ] **A4. 직각 꺾기 ㅐ/ㅔ** — → 긋고 ↓로 꺾기 ×5 → "애". ← 긋고 ↑ ×5 → "에".
      ⚠️ 순정 실측상 꺾은 획이 우측으로 휘면 ㅑ로 넘어간다(R2 #4) — 그것도 정상.
- [ ] **A5. 세로 체인** — ↑↓→ ×5 → "와", ↑↓→← ×3 → "왜", ↑↓←→ ×3 → "예",
      ↑↓↑↓ ×3 → "유".
- [ ] **A6. ㆍ 토글** — 확장형/클래식에서 ㅗ 상태에서 ㆍ 연타 → 교↔고 무한 토글.
      ㅜ에서 → 규↔구.
- [ ] **A7. 자소 백스페이스** — "갬" 입력 후 ⌫⌫⌫ → 개 → ㄱ → 빈칸.
      "이" 입력 후 ⌫ → "ㅇ"이 남는 게 맞다 (기존엔 통째로 사라졌음 — 적응 필요 여부 확인).

## B. 회귀 (이번 변경으로 깨지면 안 되는 것)

- [ ] **B1. 단독 대각선** — ↗ 탁탁 ×10 → 전부 "이", ↙ ×10 → 전부 "으".
      대각선 왕복(A1~A3)을 추가했으므로 **손을 떼며 튕기는 꼬리**가 ㅐ/ㅢ로 승격되는지가
      최대 리스크. 평소보다 대충, 빠르게 그어볼 것.
- [ ] **B2. ㅚ 꼬리** — ↑↓(외) ×10, 마지막에 손을 왼쪽으로 흘리며 떼기. "외"가
      "여"로 바뀌면 회귀 (↑↓←=ㅕ 간선 추가의 부작용 — 유닛 가드는 있으나 실제 꼬리로 확인).
- [ ] **B3. 기존 ㅐ/ㅔ 경로** — →← ×10 → "애", ←→ ×10 → "에" (변경 없이 그대로).
- [ ] **B4. 빠른 ㅛ/ㅠ** — ↑↓↑, ↓↑↓ 아주 빠르게 ×10씩. 순정도 0.2초 간격에서
      획 절단이 났으니(E 섹션) 완벽할 필요는 없고, **기존 버전보다 나빠지지 않으면** 됨.
- [ ] **B5. ㅘ/ㅝ** — ↑→ ×10 → "와", ↓← ×10 → "워". 특히 ↓ 후 ←를 살짝 아래로
      기울여도 "워" 유지 (순정 실측: ±24°까지 ㅝ).
- [ ] **B6. 순정 문장 입력** — "안녕하세요 오늘 날씨 좋네요"를 평소 속도로 3회.
      오타 위치 기록 (I1 영상과 같은 문장 — 순정 대비 비교 기준).

## C. 튜닝 실험 (측정 후 결정할 것)

- [ ] **T-1. 되돌림 등록 임계** — 순정은 되돌림을 키 폭의 29~33%부터 획으로 인정
      (R5 실측). 우리 기본 reversal 임계는 ~20%로 더 민감하다. B1/B2에서 꼬리 오타가
      나면: 설정 → 긋기 → 긋기 길이/민감도를 조절해 재확인 → 그래도 나면
      `reversalThresholdRatio` 기본값을 0.3 키폭 상향 검토 (GestureSettings).
- [ ] **T-2. ㅝ 위쪽 허용각** — ↓ 긋고 ←를 위로 15~20° 기울여 "워"가 나오는지.
      순정은 ~26°까지 ㅝ인데 우리 섹터 경계는 22.5° — 체감상 ㅟ 오발이 잦으면
      ↖ 섹터 폭 델타(설정 → 긋기 → 각도)로 보정 가능한지 확인.
- [ ] **T-3. 재해석 게이트(0.6 키폭)** — A1~A2에서 성공률이 낮으면 되돌림 획을
      크게 긋도록 안내할지 vs `reinterpretMinSecondStrokeRatio` 0.5로 낮출지 판단.
      낮추면 B1 꼬리 리스크가 커진다 — 양쪽을 같은 세션에서 확인할 것.

## D. 앱 화면 (문구·튜토리얼)

- [ ] **D1. 튜토리얼 3단계** — "대각선 왕복 — ㅐ·ㅔ·ㅢ" 화면에서 화살표 안내와 실제
      입력이 일치하는지, 연습 줄("개", "게", "의"…)이 새 경로로 통과되는지.
- [ ] **D2. 튜토리얼 6단계** — ㅞ 안내가 ↓←→로 나오는지 (표기 오류 수정 확인),
      ㅢ 대체 경로(↙↗) 병기 확인.
- [ ] **D3. 타이핑 연습 34번** — "대각선 왕복 모음 (ㅐ·ㅔ·ㅢ)" 항목이 새 경로로 통과되는지.
- [ ] **D4. 설정 문구** — 긋기 설정 순정 모드 설명에 왕복 경로 문구, 백스페이스
      설정의 "한 자소씩" 문구, 설정 검색에서 "애"/"자소" 검색 히트.
- [ ] **D5. 확장형 모음 키 라벨** — "ㅣㆍㅡ / 모음" 2줄 표기, 눌렀을 때 기능 변화 없음.
- [ ] **D6. 버전 표기** — 설정/앱 정보에서 2.0.0 (16) 확인.

## 기록 방법

실패 사례는 `(항목번호, 의도한 글자, 나온 글자, 대략의 손 움직임)` 형식이면 충분하다.
영상 판독 데이터(각도·길이 분포)와 대조해 임계값을 조정한다. 포인터 오버레이 같은
계측이 없어도 이 형식이면 원인 후보를 좁힐 수 있다.
