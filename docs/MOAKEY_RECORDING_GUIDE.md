# 순정 모아키 관찰 영상 — 촬영 가이드

> 갤럭시(삼성 모아키)에서 입력 동작을 녹화해 우리 구현과 대조하기 위한 촬영 목록.
> 판독은 프레임 추출(ffmpeg) → 궤적 확인 → `CLAUDE.md` 의 "순정 모아키 입력 스펙"과 대조 →
> 차이 나는 항목을 `GestureOverDetectionCharacterizationTests` 의 `drivePath` 로 재현·고정.

---

## 0. 촬영 전 설정 — 이거 안 켜면 절반은 못 쓴다

### ★ 필수: 포인터 위치 표시
**설정 → 개발자 옵션 → 입력 → "포인터 위치"(Pointer location) ON**

켜면 화면에 **손가락 궤적선 + 십자선**이 그려지고 **상단에 X/Y 좌표와 속도가 숫자로** 표시된다.
이게 없으면 결과 글자만 보이고 *어떻게 그었는지*는 안 보여서, 정작 알아야 할 걸 못 본다.

> 개발자 옵션이 안 보이면: 설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호 7회 탭

### ★ 필수: 탭 표시
**같은 화면 → "탭 표시"(Show taps) ON** — 터치 다운/업 지점이 찍혀 획의 시작·끝 구분이 쉬워진다.

### ★ 녹화 설정
- **60fps** 로 (긋기 하나가 약 200ms → 12프레임 남음, 궤적 재구성에 충분)
- 세로 방향 고정
- 화면 밝기 충분히

### ★ 첫 클립: 삼성 키보드 설정 화면
민감도·각도 등이 지금 **어떤 값**인지 모르면 관찰 결과를 해석할 수 없다.
모아키 관련 설정 화면을 **스크롤하며 전부** 한 번 찍어 주세요.
(저장소에 `docs/moakey_ios_custom_docs/assets/03_gesture_angle_reference.png` 가 이미 있는데,
그때와 설정이 같은지 다른지가 중요합니다.)

## 1. 촬영 방법

- **한 클립에 한 항목**, 같은 항목은 연속 3회 반복해서 한 클립에
- 메모장 등 **글자가 크게 보이는 앱**에서
- 파일명에 의도한 것을 적어주세요 — 판독할 때 "무엇을 하려 했는지"를 알아야 비교가 됩니다

```
A2_wa.mp4          # ㅘ 시도
D1_ae.mp4          # ㅐ 시도
E3_yo_fast.mp4     # ㅛ 빠르게
```

- 각 항목마다 **천천히 1회 + 평소 속도 1회** (임계값 관찰용)
- 결과가 **틀리게 나와도 그대로 두세요** — 틀린 게 오히려 중요한 데이터입니다

### D. 2차 입력의 방향 관대함 ★★가장 중요
> 이게 우리 문제의 핵심입니다. 우리는 후속 획에 **엄격**해서 "빨리 치면 인식 안 됨"이 나오고,
> 반대로 **관대**하게 하면 손 떼며 튕기는 꼬리까지 획으로 먹어 '으'가 '워'로 바뀝니다.
> 순정이 이 상충을 어떻게 푸는지가 이번 관찰의 제일 큰 목적입니다.

| # | 내용 | 파일명 |
|---|---|---|
| D1 | ㅘ(↑→) 에서 **두 번째 획을 점점 기울여가며** 3~5회 — 정확히 →, 살짝 위로, 더 위로, 거의 ↗ | `D1_wa_angle_sweep.mp4` |
| D2 | ㅝ(↓←) 로 같은 방식 | `D2_wo_angle_sweep.mp4` |
| D3 | ㅛ(↑↓↑) 에서 **마지막 획을 짧게** 3~5회 — 길게, 보통, 아주 짧게 | `D3_yo_length_sweep.mp4` |
| D4 | 첫 획을 기울여서 ㅘ 시도 (↗에 가깝게 시작 → 오른쪽) | `D4_wa_first_tilted.mp4` |

**볼 것**: 첫 획과 후속 획의 허용 각도가 다른가? 후속 획은 얼마나 짧아도 인정되는가?

## 4. 참고 — 판독으로 알 수 있는 것과 없는 것

| | |
|---|---|
| 정확히 알 수 있음 | 방향 조합 규칙, 좌표 오버레이 숫자, 획 개수, 꺾이는 지점, 조합 상태 전이 |
| 근사만 가능 | 획 등록 임계값(몇 px부터 획으로 치는지), 허용 각도 폭 — 여러 샘플에서 역산 |
| 알 수 없음 | 터치 압력·면적, 삼성 내부 파라미터 값 자체 |

**중요**: 매핑 규칙은 영상으로 확정할 수 있지만 **수치 임계값은 그대로 베낄 수 없습니다.**
좌표계도 키 크기도 다르니, 관찰한 건 "규칙"으로 받고 수치는 우리 엔진에서 다시 튜닝해야 합니다.
그래서 D 섹션(관대함)이 수치가 아니라 **경향**("첫 획보다 후속 획이 관대하다" 같은)을 알려주는 게 목적입니다.
